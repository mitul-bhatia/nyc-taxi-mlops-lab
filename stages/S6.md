# S6: RAG (Day 2, 12:00–13:15)

**Goal:** riders can ask the app why their ETA is what it is, and get answers grounded in the company's ops wiki (policies no model has seen), with every answer traced. The wiki is re-read daily, and only what changed is embedded again.

## Recall check (5 minutes, no agent)

1. What does retrieval add that fine-tuning doesn't, and what does it cost per request?
2. Cosine distance between two embeddings: what does a small one mean? Why must a question and a document be embedded by the same model?
3. An HTTP ETag: what does `If-None-Match` save, and what does a 304 carry?
4. HNSW and IVFFlat: what does each one trade?

## Given

- **The LLM host:** `deploy/compose.llm.yaml` runs llama.cpp twice, chat (Qwen3-4B-Instruct-2507, port 8080) and embeddings (nomic-embed-text-v1.5, 768 dimensions, port 8081), and is deployed by `.github/workflows/llm.yaml` through a runner on that host. The first deploy downloads 2.6 GB of models. It's a CPU: an answer with wiki excerpts takes 45–70 s the first time (the prompt is read at about 13 tokens/s, then 7.5 tokens/s are written), and a few seconds less when the prompt's beginning is already cached.
- **`contracts/assistant-openapi.yaml`** (frozen): `POST /assist` on the app.
- **The app's assistant** (`app/src/rideapp/assistant.py`): embeds the question, calls your retrieval, builds your prompt, asks the chat model. Until you build retrieval it gets no wiki context, so try it first and see what the model makes up.
- **Tracing** (`app/src/rideapp/tracing.py`): Langfuse, on as soon as `lab/langfuse` has your project's keys.
- **The pipeline side:**
  - `labpipes/wiki.py`: the wiki client, with ETags and Retry-After.
  - `labpipes/chunking.py`: `chunk_markdown(title, body, max_tokens, overlap_tokens)`.
  - The `wiki`, `embed` and `rag` resources.
  - The platform stack creates a `rag` database on RDS (pgvector 0.8.1 is available there).
- **Credentials:** the wiki's URL and your token arrive from the instructor. They go in Secrets Manager (`lab/wiki`), never in the repo.

## Build

1. **LLM host (15 min, mostly waiting):** register its runner (`scripts/register-runner.sh llm`), then `gh variable set LAB_LLM --body on` and `gh workflow run llm.yaml`. While the models download, allow the app host to reach the embedding port: add the rule in `infra/live/security.tf`, add an `llm_private_ip` output, apply, and `gh variable set LLM_HOST --body "$(terraform -chdir=infra/live output -raw llm_private_ip)"`. Then pass `LLM_HOST` to your CD (the app reads it) and redeploy the app and the platform.
2. **Wiki credentials:** `aws secretsmanager put-secret-value --secret-id lab/wiki --secret-string '{"url": "...", "token": "..."}'`.
3. **Ingest (25 min):** in `pipelines/src/labpipes/defs/rag.py`, build:
   - `wiki_pages`: conditional GETs.
   - `wiki_chunks`: content-hashed chunks.
   - `wiki_embeddings`: only chunks without a vector.
   - A blocking completeness check and a daily schedule.

   Run it twice with `scripts/dagster-run.sh ingest_wiki --wait`. The second run should fetch nothing and embed nothing. Prove it from the run's metadata.
4. **Retrieve and prompt (20 min):** in `assistant.py`, write `retrieve` (top-k by cosine distance from `rag.chunks`) and `build_messages`. Keep the system prompt fixed and put the excerpts in the user turn, so llama.cpp can cache the prefix. Ask the same question as in step 1 and compare.
5. **Trace:** create a `lab/langfuse` secret container in `infra/live/main.tf`, apply, and put your Langfuse project's keys in it (`{"host": "https://cloud.langfuse.com", "public_key": ..., "secret_key": ...}`). Redeploy the app, ask a question, and find the trace: which chunks came back, how long the generation took, how many prompt tokens there were.

## Decision points (one record each in `decisions/`)

- **Chunk size, overlap and top-k:** use evidence. The wiki's pages are short, every chunk costs about 11 s of prompt processing on the LLM host, and an answer is only as good as the chunk that holds it.
- **HNSW or IVFFlat:** what each needs to build, what happens to recall as the wiki changes, and what you'd pick at a million chunks.

## Done when

- `curl -m 150 -X POST http://<app_public_ip>/assist -H 'Content-Type: application/json' -d '{"question": "..."}'` answers a question about a wiki-only policy correctly, with that page among `sources`, and a `trace_id`.
- A second `ingest_wiki` run shows 0 pages fetched and 0 chunks embedded.
- The trace is in Langfuse with the retrieval and the generation.
- `make check` passes, and your two new decision records exist.
